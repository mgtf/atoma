# Local MCP complexity campaign — 2026-09-08

Four sequential application builds exercised a persistent Kanban and an inventory app with stock movements, immutable history, validation, summaries and a browser UI. The first build ran in an isolated operator store and was therefore invisible to the project viz. Following operator feedback, the next three builds used authenticated Streamable HTTP MCP at `http://127.0.0.1:5173/mcp`, attached to the local Kanban progression and Inventory progression projects. A separate configuration refusal before those three builds made no model calls.

No build completed orchestration within the campaign's fifteen-minute limit. The isolated build timed out; all three live MCP Tasks were cancelled through MCP at the limit. Preflight confirmed lease cleanup. None published a delivered artifact. Independent checks against copies of the generated applications passed 18/18 and 17/18 for Kanban, then 14/15 and 14/15 for inventory. The MCP Kanban lacked editing existing task title/priority. The first inventory overflowed horizontally at 390px; the second fixed that but omitted search entirely (confirmed in both HTML and JavaScript, not merely a selector mismatch). API persistence and real browser creation/movement checks passed in both inventory versions.

This is exploratory incident evidence, not a controlled learning benchmark. Initial registry states differ; the last run uses a corrected browser tool plus explicit mobile feedback. Shared project state was not reset, and the complete starting product store was not snapshotted. There is no basis to attribute differences to learning alone. Four builds consumed 129 model calls and USD 5.5708053 in recorded API-equivalent subscription cost, not additional API billing. Exact per-run totals and identifiers are in measurements.json. Scores cover the named executing checks, not every possible requirement or security property.

Two framework defects were reproduced and corrected:

- An identical MCP request during an active run was rejected by the run lease before idempotency lookup. Project lookup now precedes acquisition, with a recheck on contention. A real HTTP regression uses two SDK clients, real SQLite lease/store/coordinator and a held mock driver. Live MCP confirmation returned the same run for exact retries while changed goals and new concurrent requests remained rejected.
- Selector-based browser interaction calculated viewport coordinates without bringing offscreen targets into view. The tool now scrolls the resolved element before reading its bounding box. The regression failed before the fix and passed afterwards; the compiled Linux worker independently typed quantity 375, preserved the previous field and clicked a distant button.

Validation: full check passed with 3,556 tests and four skipped; both TypeScript configurations, lint and documentation checks passed. Worker build and 18 container isolation tests passed. A stale translation assertion was made deterministic with an injected translator; target locale catalogs were not changed. The source patch is included in the evidence, based on initial HEAD 6e9af3c. Unrelated working-tree documentation edits are excluded. The corrections and campaign evidence are committed together; no push is part of this campaign.

The MCP exercise covered authentication, its 37-tool catalogue, project listing/creation, Tasks launch/status/cancel, bounded traces, status resources, idempotency and concurrency refusal. The dedicated temporary token was revoked, audited and tested to return HTTP 401, then its secret file was removed. The local viz remains running. App previews returned 503 because this deployment has no preview runtime; project trace visibility and app preview availability are distinct. Existing local account model pins and the explicitly selected host subscription organisation remain configured for future runs.

The evidence archive preserves goals, harnesses, scorers, raw traces, workspaces, skill snapshots, original/final scorer logs, screenshots, build/test logs, source archive and corrective patch. Scorers run in disposable network-disabled containers, copying read-only original workspaces before writing test data. Stock selectors were adapted to each actual UI without changing functional obligations. Kanban favicon diagnostics and the DOM-rerender race in the scorer are retained with their corrected reruns; no generated application was hand-fixed for scoring.
