Autonomous iteration session: run → analyse → fix → next run, against
`ATOMA_LLM=claude-cli` on a store reset on 2026-08-19. Every number below is
reproducible from `burnin/results-2026-08-21.csv` and the traces under
`runs/`. Cost is the estimated API-price equivalent from recorded model tiers,
not subscription billing — the burn-in harness prints that caveat itself.

## What was fixed, and what the measurement said afterwards

**1. Two French lines on the runner's stdout** (`9213ced`). That stream is an
API — burn-in parses it — and everything else on it is English.

**2. Skill distillation manufactured SEMANTIC TWINS** (`9213ced`).
`learnSkillFromRun` never showed the model the ids it had to avoid; the only
guard is exact-id equality. Batch 1 learned 11 skills of which **6 were three
twin pairs on the same molecule**. Promotion needs the threshold successes on
ONE id, so two half-credited twins never reach it while both compete for every
match. The distiller now receives the visible namespaces' ids and
`when_to_use` lines and is told to emit the EXISTING id or nothing.

Evidence after: two task-skill distillations have run since, neither a twin
(the whole 12-skill store shows no pair above `--sim 0.35`). That is weak but
consistent. The three RECOVERY skills learned since came through
`learnEventSkillFromRecovery`, a path this fix does not touch.

**3. A synchronous smoke cannot observe what the page updates asynchronously**
(`ab4e9b5`). Batch 1's click-counter spent 19 `validate_html` calls and $0.52
of execute tokens because `#count { transition: all 0.3s ease }` means a
`getComputedStyle` read taken right after the class toggle returns the
PRE-transition value. Trace evidence: `inlineStyle:"red"` beside
`computedColor:"rgb(51, 51, 51)"`. The model "repaired" its already correct
CSS by adding `!important`, which does nothing to an animation. Verified in
Chrome: sync read → `rgb(51, 51, 51)`, async read awaiting 400ms →
`rgb(255, 0, 0)`.

Batch 2 then showed the batch-1 wording ("colour, size or opacity") was too
narrow: `web-stopwatch` regressed and returned
`{ elapsed: 988, running: true, display: "00:00.00" }` — the clock advanced
because `getElapsedMs()` reads `Date.now()`, the display stayed at zero
because the `setInterval` tick could not run. Same mechanism, one level up. So
the guidance now states the LAW and `SMOKE_CANONICAL_STATE_SHAPE` — the
template the model actually copies — is async.

**4. My own regression from that fix** (`7da079e`). The async shape worked (21
of 22 smokes in batch 3's countdown were async) and then the model generalised
"await one repaint" into "await 33 seconds for a countdown". Two smokes were
killed at `CDP_PROTOCOL_TIMEOUT_MS`, each having burned ~45s, and the run
failed on its 900s budget. The await is now BOUNDED, and Puppeteer's
"Increase the 'protocolTimeout' setting" — advice for whoever builds the
harness — is replaced by the remedy the `holdMs` description already gave.

Batch 4 re-ran both web goals verbatim:

and the model used `window.__test.advance(ms)` — the hook the guidance points
at — instead of waiting on real time. `web-progress` came down with it:
$0.8356 → $0.4905, 662s → 425s.

**5. `write_file` persisted an unreadable `.atoma-probes.json`** (`7da079e`).
Three model writes in batch 3's web-progress: 3019B valid (created), 3464B
valid (merged to 6445B), then 10857B carrying a RAW NEWLINE inside a string
("Bad control character in string literal at position 6408", charCode 10).
Byte-identical in/out proves the merge returned it verbatim by documented
policy. Position 6408 is exactly where the supervisor's zero-token
ground-truth probe then reported MALFORMED, so the validator rejected and the
run paid a full extra execute cycle repairing a file the tool had accepted —
having been sent down that path by `edit_file`, which refuses the surgical
edit and says "write_file the whole document after read_file". Only the
INCOMING document is checked now, so repair still works.

## Predictions that failed

Each batch's predictions were written down before it ran; five of fourteen
failed, and two of the failures were the session's most useful findings.

- Batch 2 P2 (web-counter ≤ 8 `validate_html`): missed at 10, and the three
  pre-flight refusals still fired TWICE EACH. Writing the rules into a block
  I had just made longer bought nothing.
- Batch 2 P3 (web ≤ batch 1's second web task): `web-stopwatch` regressed
  +28% — and that regression is what revealed the general law above.
- Batch 3 Q2 / batch 4 R3, R4: call counts improved a lot and still missed

Web variance is wide — the same two goals cost $0.31 / $0.40 / $0.72 / $0.84 /
$0.49 / $0.56 across four batches. Single-run web deltas are not evidence;
only the repeated failure SIGNATURES are.

## Handed forward, deliberately unfixed

**A. A browser-verification phase was re-routed to the HTTP molecule.** Batch
3's web-progress phase 2 read "serve it with a local static server and load it
in a real headless browser". Routing: Meristem → Tracheid (correct) → Water
(correct), whose plan the validator rejected legitimately; then Tracheid →
**Methane**, which has no `validate_html`. The off-scope plan gate refused
Methane's plan and coached it to stay inside its toolset, so it spent
`write_file`×9 and `run_shell`×6 trying to verify a browser UI over HTTP — and
the distiller saved that dead end as `verify-ui-state-transitions-headless-browser`,
a recipe telling future runs to write a script that launches its own headless
browser. The recipe is dropped; the routing gap is untouched.

The gate's remedy is the wrong one here: "do what IS achievable in scope"
means fabricating a browser. When a subtask's capability bucket demands a tool
no candidate child declares, that looks like a CREATE/branch signal rather
than a coach-in-scope signal. Note also that the distiller's toolset filter
passed the draft — Methane really does declare `start_node_server` and
`run_shell` — so in-scope is not the same as executable.

ONE observation, one batch. AGENTS requires two consecutive batches before
acting on a friction signature, and cooling-off forbids designing the
mechanism in the session that surfaced it.

**B. The rgb()/rgba() literal refusal, now four batches deep.** It fired 11
times across five web runs — 2, 2, 4 and 3 per batch — and every occurrence
costs a model turn. The guard exists for a good measured reason (a model once
GUESSED a green value and rewrote correct CSS eleven times). But a model that
READS the value from source and awaits the transition is making a sound,
deterministic assertion, and the guard refuses it categorically on tasks whose
requirement literally is "turns amber". Whether the refusal should become
conditional, or whether the class-marker route should simply be made
unmissable, is a design question with a real trade-off on both sides. It is
the first thing to settle next session, and it should be settled once, against
this evidence.

**C. No way to retract a MISATTRIBUTED failure.**
`build-inline-html-widget` reached 7✓/2✗, both failures inherited from the run
that died on its budget because of my unbounded await — an environment
failure, which AGENTS says is not evidence against a recipe. With failures>0
it can never be promotion-eligible again, and `skills reset` is all-or-nothing:
removing 2 wrong failures cost 7 right successes.

## Measured and rejected

Four tempting changes died on evidence, recorded in AGENTS.md so they are not
re-proposed:

- **Batching the pre-flight refusals** into one response: every refused
  payload across both batch-1/2 web runs violated exactly ONE guard. Zero
  round-trips saved.
- **Moving the rules to the call site**: the erased-intermediate-state rule is
  ALREADY in the `smoke` parameter description and was violated six times
  anyway. Placement is not the untried variable.
- **Lowering the `skills stats --sim` default**: three known twin pairs score
  0.41 / 0.39 / 0.26 while a build-vs-probe FALSE positive scores 0.31, so no
  threshold on lexical overlap separates them and the 0.5 default surfaces
  none of the three. Prevention belongs at learn time.
- **Auto-repairing a refused smoke**: it would fabricate the evidence the tool
  exists to produce.
