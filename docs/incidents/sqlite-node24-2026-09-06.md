# Native SQLite crash during the supervisor production test

## Observed evidence

Production revision `daaf7f461af562359193c48d3f92bd5fac5ac261` ran with
`/usr/bin/node` v24.20.0 and better-sqlite3 11.10.0. Project run
`4d3429df-096e-4987-a196-e438da23ba9a` started at 01:38:06 UTC. At 01:38:40,
the control plane aborted with this native stack, supplied by the operator:

```text
node::RemoveEnvironmentCleanupHook(v8::Isolate*, CleanupHook, void*)
Assertion failed: (env) != nullptr
Statement::~Statement() [.../better_sqlite3.node]
systemd: Main process exited, code=killed, status=6/ABRT
```

The operator did not restart the service. Systemd restarted it at 01:38:46;
recovery marked one interrupted project run failed. At 01:40:47, immediately
after the analyst announced the cancelled run, the same native assertion
aborted the replacement process. This is not an exception the analyst can catch.
No mender dispatch or correction PR had been observed for this test.

A later analyst retry reported `Codex profile lease could not be acquired`.
This was a separate configuration failure: `/home/atoma/.codex` was absent and
its parent was root-owned mode 0755. The service cannot create the profile's
sibling SQLite lease there. The operator moved the analyst profile under
`/home/atoma/state/codex/analyst` and configured the actual binary path,
`/home/atoma/state/.local/bin/codex`. The analyst was disabled during repair.
No live lease file or trace was deleted.

## Correction and compatibility limits

Pin better-sqlite3 to 13.0.3. Its
[Node-API rewrite](https://github.com/WiseLibs/better-sqlite3/releases/tag/v13.0.0)
removes the legacy ObjectWrap implementation involved in the native destructor
stack. Node's [cleanup-hook change](https://github.com/nodejs/node/pull/63642)
and the [upstream report with the same assertion](https://github.com/tobi/qmd/issues/827)
support this choice. They do not establish which allocation caused our GC.

The new driver's binding declares `NAPI_VERSION=10`. Despite its broad upstream
`>=22` engine metadata, Node 22.13.0 cannot load that binary: the local tests
segfaulted in `napi_module_register_by_symbol`. The
[Node-API version matrix](https://nodejs.org/api/n-api.html#node-api-version-matrix)
puts version 10 at Node 22.14.0 or newer. Raise the repository's 22.x floor,
doctor, CI pins and mender image together; continue supporting Node 24+.

Core CI runs the entire release check on 22.14.0 and the observed production
runtime 24.20.0. The compiled release smoke now exercises cached store queries,
short-lived readonly run-lease readers, lease contention/reacquisition, explicit
close and asynchronous major GC in a bounded subprocess, then checks persistent
rows and SQLite integrity. The host deployment runs it against the freshly
installed production dependency before activating the release.

Standalone pressure tests did not reproduce the old production assertion on
Linux, including with a locally rebuilt 11.10.0 on Node 24.20.0. The smoke is
compatibility coverage of the real compiled paths, not a deterministic
red/green reproduction of the original GC crash. A successful production
analyst retry and run remain necessary to close the end-to-end incident.
